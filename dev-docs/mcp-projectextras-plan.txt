Recommended integration
Add mcp/mcpprojectextras.cpp/.h with toolCatalog() and callTool(owner,name,args,state,stateReader), matching mcpmedia/mcpprofiles. A per-server QObject owns at most one document replacement/archive operation and bounded terminal job records. Native work runs on the GUI thread; only immutable file-copy/compression plans run in workers. Use existing whole-project expectedState and bounded response receipts. Separate job acceptance, needsUserAction, cancellation requested, and verified completion. Never infer completion from a dialog closing or document.loading becoming false. Archive the verified 0.4 baseline before these native changes.

Build in this order: notes + non-destructive cleanup; source creation; checked OTIO; native library serialization; archive/extraction. Keep all R36 requirements open until the last semantic proofs pass. This order permits independent regressions without treating the first steps as R36 completion.

1. Notes and cleanup (smallest coherent first implementation)
Native entry points: ProjectManager::documentNotes()/setDocumentNotes(), NotesPlugin::widget(), NotesWidget (QTextEdit), ProjectManager::prepareSave(). Saving writes kdenlive:documentnotes and version2 into main_bin. mcpstate already hashes the actual NotesWidget when GUI exists, and saved bin HTML headlessly. NotesWidget has its own QTextDocument undo history; it is not the document timeline QUndoStack. setDocumentNotes ignores empty input and setHtml resets native note history, so it is not a complete edit API.
Proposed get_project_notes returns plain/rich native content, bounded format spans/anchors, revision and note canUndo/canRedo. edit_project_notes performs bounded UTF16 cursor edits and native character/paragraph formatting inside one QTextCursor edit block; structured timecode anchors bind explicit bin UUID or sequence/track IDs and frame rather than relying on monitor focus. Preserve existing rich fragments. Expose undo/redo explicitly as notes history, report timeline undo unchanged, and let native textChanged mark the document modified. Reuse native formatting/anchor parsing rather than accepting unrestricted remote-image HTML. GUI absence is an explicit prerequisites error for edits; read-only saved notes still work headlessly.
Native cleanup: MainWindow::slotCleanProject -> ProjectItemModel::requestCleanupUnused() creates one native undo. It iterates cached m_allItems; a checked overload should accept the exact prepared attached-bin IDs, use live children, preflight readiness and every sequence reference, then requestBinClipDeletion in one undo transaction. Existing edit_bin already removes individual unused entries, so reuse that logic. get_project_files/prepare_cleanup must expose the exact manifest and hashes before clean_project applies it. Default cleanup removes only bin entries and preserves all source files. ProjectSettings::slotDeleteUnused -> requestTrashClips is a separate permanent-delete path: despite its name, requestTrashClips calls QFile::remove and discards results without undo. Do not wrap it as safe trash. Full disk-cleanup support needs per-file checked results, explicit exact-path acknowledgement and a separate non-undoable contract; test only generated owned files. Cross-source aliases, inactive/nested sequences and redo branches must be covered.
Proof: actual NotesWidget + saved/reopened native HTML/Unicode/anchors, note undo separate from timeline undo; stale/manual notes edits invalidate expectedState. Cleanup generated used/unused/shared/inactive sources, one undo restores IDs/metadata, original file hashes unchanged. Explicit disk cleanup error/denial tests must show no unlisted path touched.

Native tests/otiotest.cpp has tracks/clips, guides/markers, colors, mixes, missing media, no clips and no tracks. This is a code/result-contract gap, not a missing dependency.
OtioExport::exportFile is void; private exportTimeline writes directly with to_json_file and only logs/displays errors. Add a checked export result/native overload used by both GUI and MCP; export to owned temporary .otio, parse it back, then publish without replacement. Return terminal imported-native-state evidence and loss/missing-media diagnostics, not merely loading=false. Preserve GUI's interactive missing-media decisions as needsUserAction where required. Native .otio JSON is the implemented route; additional adapter formats are not supplied by this C++ API.
Proof: execute existing otiotest plus MCP native and actual GUI imports/exports for all existing dataset cases, fractional-rate/source timecode/track order/mix/marker cases, malformed any-dictionary values, missing external references, dirty document refusal and write errors; compare native state after saving/reopening and inspect rendered frames/audio.

Persistent library filesystem edits are not timeline undo; import creates native bin undo, placement/expansion has separate native history.
Proof: isolated configured library, selection and zone files parsed through MLT, reimport into second native document, compare tracks/timings/effects/mixes/groups and rendered AV; rename/move/delete exact requested entries only, no source-media deletion, duplicate name and symlink/traversal refusal.

5. Archive, extraction and project-file manifest
MainWindow::slotArchiveProject calls prepareSave, projectSceneList, KdenliveDoc::extractCompositionLumas/extractExternalEffectFiles then constructs ArchiveWidget(snapshotXML,...). ArchiveWidget categorizes media, slideshow dependencies, titles, playlists, proxies and subtitle files, rewrites XML through processMltFile/processTitleFile/processPlaylistFile, and supports directory/ZIP/tar.gz plus timeline-only/proxy-only. Current implementation tightly binds mutable UI widgets, KIO copy jobs, QFuture workers, private start/cancel slots and modal overwrite dialogs. archivingFinished(bool,error) covers compressed work; uncompressed paths finish through private slotJobResult; extraction exposes success-only extractingFinished and opens failure dialogs from its worker. closeAccepted can synchronously wait. These are concrete native API/lifetime gaps; do not report generic UI job return as completed archive.
Extract an immutable native ArchivePlan + owned native operation from the existing relocation routines, with checked progress/result/cancel signals; GUI widget delegates to the same service. get_project_files/prepare_archive returns all selected files, sizes, source hashes, replacements, missing files and expanded-size budget. start_archive verifies prepared whole-project/file state, writes only an owned new staging destination, validates archive/project/media references, then publishes without replacement. Cancellation is acknowledged separately from terminal cleanup; no blocking GUI wait or widget access in worker. Source files and current document URL/history remain unchanged.
Extraction must inspect entry paths/links/expanded bytes/count before copy, refuse traversal/symlinks/existing targets, extract to owned staging, validate .kdenlive XML/dependency paths, and publish the new directory. Opening it is a separate lifecycle operation. Current KArchive/KIO prerequisites are installed (KF6Archive.dll and KF6KIO*.dll); ZIP/tar codec runtime needs executed proof. Archive portability must include all subtitle languages, embedded/linked title assets, lumas, proxies, nested playlists/sequences and same-name collisions, not only ordinary AV files.
Proof: generated multi-folder project with duplicate filenames and each dependency class; directory/ZIP/tar.gz roundtrip through extraction + native reopen and AV samples; exact source hashes unchanged; cancellation during copy/compression and failures leave no published partial target; hostile archive paths and changed prepared files fail before writes.
